# 全项目代码整洁度审查

依据 [代码美学](../code-style.md)，审查执行链路、持久化、公开投影、浏览器状态、gateway 和共享协议。保留现有 lint 阈值，没有用新增豁免掩盖问题。

## 第一轮：责任与设计注释

上一轮清理删除了必要的设计解释。本轮把决定放回实现和端口旁，重点说明顺序改变的后果、跨进程承诺和恢复取舍：

- [执行生命周期](../../apps/agent/src/application/execute-run.ts)：准备阶段也受租约约束，失去归属后不能发起新的模型请求；销毁前等待续租循环结束。
- [执行完成](../../apps/agent/src/application/complete-execution.ts)：模型返回之后，仍要等待进度写入和工作区保存；失败运行也可能持有付费任务的 job ID。
- [输入控制](../../apps/agent/src/application/control-run.ts)：先记录投递意图以避免不确定工作被自动重放，同时明确这会留下“已记录意图但模型未消费”的崩溃窗口。
- [执行持久化](../../apps/agent/src/infrastructure/persistence/execution-store.ts)：会话锁与运行锁的顺序，以及检查点、释放会话和终态事件的原子提交。
- [队列](../../packages/queue/src/redis-mailbox.ts)与 outbox：ACK 代表持久接收；先发布、后提交允许重复，反过来会丢失消息；阻塞读取不能占用发布连接。
- [公开投影](../../apps/server/src/modules/conversation/infrastructure/persistence/execution-results.ts)与 [SSE](../../apps/server/src/modules/conversation/presentation/http/sse.ts)：顺序缺口暂不 ACK；消息与游标共用事务快照；一个变化展开为多帧时，最后一帧才推进游标。
- harness、工作区和沙箱端口补充不可从签名推断的约束，如超时单位、相对路径、不可变版本、flush 仍可能调用模型。

注释使用英文，不给简单赋值、入口文件和再导出添加重复说明。

## 第二轮：代码形状与多余分支

| 发现                                            | 修正                                                            |
| ----------------------------------------------- | --------------------------------------------------------------- |
| `commandsRelay` 只转发一次调用                  | 在装配根直接装配 relay，删除转发函数                            |
| 浏览器 `begin` 与 `upsert` 重复实现同一替换规则 | 合并为按 ID 原位替换，保留消息顺序                              |
| 用户和助手快照映射复制同一段代码                | 合并共同映射，显式保留发送方差异                                |
| 历史映射把 reasoning 兜底成空助手消息           | 显式排除 transcript 中的 reasoning，保留独立实时通道            |
| 活动转换后再检查是否为活动                      | 用收窄的输入和返回类型表达约束，移除不可能分支                  |
| gateway 和 token 解析的 try 同时包住解析与校验  | try 只负责可能抛出的解码/解析，校验在其后进行                   |
| token 的 wire 类型和手写字段校验重复定义        | 使用项目已有的 Zod，由 schema 推导类型，解析结果从 unknown 收窄 |

## 第三轮：注释真实性与生命周期验证

校正了旧注释中“首次加载总会重放构建快照的事件”“推理从不展示”等误导性说明及失效章节引用。另将 SDK 成本占位与真实计费区分开；签名令牌只证明请求归属，不宣称实现了额度和计费。

核对 SSE 清理语义时发现：请求取消后，如果正在等待的数据库查询同时失败，catch 会提前返回，流没有 close。新增行为测试先复现了 5 秒超时；修正后，流正常结束。没有增加重试层或吞掉未取消请求的真实错误。

## 全量复查：三个独立上下文

根据截图反馈，将范围扩大到全项目。三个 reviewer 使用不继承对话历史的新上下文，分别先读代码规范与架构，再逐文件审查：

| 范围                               | 重点                                                    |
| ---------------------------------- | ------------------------------------------------------- |
| server 全应用及公开事件集成测试    | HTTP 身份与权限、协议映射、SSE 生命周期、产品事务与装配 |
| agent 全应用、迁移、发布脚本及测试 | 执行生命周期、租约、输入控制、检查点、SQL、pi 与沙箱    |
| web、gateway、四个共享包及测试配置 | 状态变换、转发边界、共享接口、协议注释与声明顺序        |

主审补查根配置、数据库脚本、跨应用测试、skill 脚本、部署文件，并复读上述关键链路。生成的 schema 只验证，不手工排版；历史迁移保留原样。通读不意味着每个文件都需要改动。

这轮以可读性和实际职责为依据，不靠注释数量或新增目录衡量质量：

- 路由注册现在集中列出具名 HTTP 操作；身份读取统一为路由 middleware，权限仍在会话用例中。未知路径仍返回 404。
- 公开事件转换按快照、增量、终态与文本协议组织；入口位于细节前。SSE 区分 reader cancel 与请求 abort，保留既有关闭语义。
- 执行和持久化按准备、运行、保存、提交、清理分段；SQL 展开查询条件、锁定与提交内容。没有改变事务边界或锁顺序。
- 删除没有生产消费者的 `Files.uploadUrl`、只改名的 token 包装；Provider 类型由现有 schema 推导。
- gateway 的 `onSpend` 改为 `onForwardRequest`：它记录授权后的请求尝试，包含轮询，不能当作扣费收据。
- 修正旧注释中的上传职责、链接过期、运行恢复和同步媒体请求的未知结果说明。测试名称与断言保持一致，生成脚本测试逐个清理临时目录。
- `tooling/database` 改为 `scripts/database`；依赖检查配置移至根 `.dependency-cruiser.cjs`。同步命令、类型检查范围、lint 配置、测试导入与文档。
- README 与架构文档明确 `deploy/database/schema.sql` 的生成来源，以及四个共享包各自的内容和消费者。

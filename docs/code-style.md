# 代码规范

**less is more**：保留现有行为，用最少的概念表达实际责任。文档用中文，代码、注释、错误和测试名用英文。

## 结构

- 相邻放置一起变化的代码和测试；目录按责任划分，不按技术层机械分组。
- 优先用函数和数据。class 只用于真实实例状态、资源生命周期或外部 API 要求。
- 不创建纯转发 service、repository、barrel、单实现注册表或备用实现。
- 只有真实消费者需要才导出；只有非平凡复用或独立责任才抽 helper。
- 函数按清楚的阶段线性展开，提前返回；不为缩短行数拆散同一决定。
- 命名说明实际事实或动作，文件用 kebab-case。自有身份字段用 `ID`，官方协议字段保持原名。

## 类型与解析

- 外部输入在 HTTP、配置、消息、工具或供应商边界解析，wire 类型从 schema 推导。
- 同进程已知类型不重复解析。相邻不透明身份用具名参数，避免交换后仍能编译。
- 非法状态用判别联合排除；闭合分支保持穷尽检查，不用 `any` 掩盖不匹配。
- 接口只包含消费方实际需要的能力；函数成员用属性语法，保留严格参数检查。
- 配置和默认值集中在 `packages/config`，进程启动时解析自身投影；业务函数不读取环境。
- 空配置视为缺失，一次列全安全诊断，不回显凭据。

## 权威与失败

- 具名 SQL 事务拥有最新授权、锁序、唯一约束与原子写入；纯规则不依赖 SQL、HTTP 或 SDK。
- PostgreSQL 是事实权威，Redis 是至少一次投递；持久接受后 ACK，准确区分重放与冲突。
- 未知创建、付费请求、PUT 或 COMMIT 结果不能当作失败后安全重试，不自动换环境或重新推理。
- SQL fence 不会阻止旧进程操作 VM；失效或未知资源结果需要隔离。
- 公开错误与私有原始原因分开。取消请求、已发停止请求和实际收尾不是同一个事实。
- 资源创建者负责停止、等待、关闭；浮空 Promise、定时器、监听器和子进程都有明确 owner。
- 注释解释不直观的权威、SDK 限制和恢复理由，不复述语法；空 catch 说明吞掉失败的依据。

## 检查与 review

`sh scripts/check.sh` 执行严格类型、type-aware lint、Prettier、依赖边界和单元测试。配置文件是工具规则的唯一来源，不复制或放宽阈值来制造通过。

行为测试保护权限、精确重试、并发赢家、授权过期、资源收尾和未知结果，不断言私有结构或转发仪式。缺陷先复现失败；保持语义的简化使用现有行为测试验证。

review 看实际实现、调用方和 diff：删除后是否只是少一次跳转，是否丢失权威或恢复语义，还有没有无消费者的文件。分别报告当前检查结果和未验证范围，不引用历史绿色。

迁移只前向修正；生成物不手改，第三方 SDK 只用官方发布包与公开 API。生成来源与发布边界见 [generation.md](generation.md)，应用责任见 [architecture.md](architecture.md)。

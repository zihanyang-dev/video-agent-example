# 架构

## 产品与进程

```text
用户
└─ conversation / thread（界面叫 Chat）
   ├─ 消息与单轮执行
   ├─ assets：上传文件和交付文件
   └─ 可恢复的 sandbox

React web → Caddy → server → Redis Streams → agent → sandbox
                         ↘ PostgreSQL       ↗
                         ↘ 资产对象存储     ↗
```

thread 是持续对话的唯一身份。执行是会话的一轮，不是另一个业务领域。资产与执行环境属于会话，没有 project、第二个 Chat 标识、成员或共享权限体系。

- **web**：登录、Chat、消息、资产和运行视图。
- **server**：身份、会话归属、消息与资产事实、请求接受、执行命令投递和公开结果接收。
- **agent**：会话执行、租约、官方 pi、沙箱工具与原生环境保存。
- **Caddy**：静态托管与同源 `/api` 代理。

数据库权限按进程分开：server 使用 auth/product，agent 使用 execution。这个安全边界不改变执行属于会话的产品关系。

## 会话的一轮

```text
HTTP 解析与身份验证
→ 产品事务：锁读 thread、裁决重放、写消息与命令 outbox
→ Redis 投递
→ agent 持久接受后 ACK
→ 领取会话租约、连接或恢复 sandbox
→ pi 与工具执行、等待停止与环境保存
→ 执行终态与事件 outbox
→ server 持久接受后 ACK
→ 产品快照与官方 AG-UI
```

PostgreSQL 是事实权威，Redis 负责至少一次投递。稳定标识、精确重放、冲突拒绝、接受后 ACK 和 retained outbox 保护未知回执；不宣称端到端 exactly-once。公开事件有持久 ordinal 与重连游标。

同一 thread 的执行由数据库租约串行化。锁后数据库时间、owner、run 与 fence 决定写入权威。过期的付费运行明确中断，不能自动重新推理。浏览器断线不取消执行；取消是独立的持久请求，界面区分停止请求与真实终态。

具名 SQL 操作拥有最新事实、锁序、约束与原子变化。纯规则只接收必要事实。HTTP 可以直接调用事务函数，不添加纯转发 service。外部网络动作不冒充数据库原子性；行锁内 outbox 发布是明确的可靠性选择。

## 身份与授权

Better Auth 使用 PostgreSQL 服务端会话和 GitHub provider。Cookie、可信 Origin、CSRF、回调限制和账户绑定由服务端负责；没有固定 operator 或生产测试绕过。

身份来自会话，归属由最新 thread 事实决定。请求不能声明 owner。外人的标识返回不泄露存在性的拒绝。写入事务锁读归属与归档状态，事务前预检查不是最终授权。

注销先持久撤销，再过期 cookie。SSE 每批重新检查会话和归属；到期阻止继续读取，但不等于取消已接受工作。归档拒绝新写入并请求停止未结束运行。

旧 owner 文本通过显式映射归给已存在的认证用户，不自动认领或改变原消息、运行及历史标识。

## 资产

上传和交付共用资产元数据、授权与读取流程；来源决定写入权威：用户上传由身份和 thread 归属裁决，Agent 交付由有效执行身份及完成事实裁决。

消息引用已完成且属于该 thread 的资产。agent 只得到 server 分配的引用，不接受任意对象 URL。选择资产属于消息重放意图，空文本加资产是有效输入。公开 DTO 不包含对象 key、长期凭据或模型私有历史。

Agent 自主决定 guest OS 的文件布局。导入资产和交付文件是明确动作，不扫描固定目录推断产物。中间文件不自动公开。

对象存储保存资产字节，SQL 保存归属、摘要、上传完成与消息关联。上传成功但 SQL 回执未知不能盲删对象。代理读取重新验证用户并受大小、并发和超时约束。

文件接收、模型理解和工具处理是不同能力。图片采用官方 pi 输入；音视频理解与处理必须有实际模型或工具证据。材料不是高权限指令。

## 沙箱环境与生命周期

每个 thread 关联一个可恢复环境。首次创建，后续连接或恢复，空闲原生保存/暂停，明确回收时删除。不每轮复制整个目录，不规定工作文件夹，不把 workspace 建成产品实体。

文件系统、COW、脏页、节点缓存和按需加载由供应商实现。应用保存供应商标识和不透明原生引用；模型私有历史仍属于执行数据库。

文件系统保存与内存保存语义不同。内存恢复会继续原进程，外部连接和付费请求的状态不会随 VM 一起保存。工具停止、环境暂停与 SQL 提交不是一个分布式事务，失败和未知结果必须明确。

SQL fence 不会阻止旧 worker 操作 VM。租约过期、旧进程失联或远端结果未知时隔离环境，未经确认不自动交给下一轮，不静默创建空环境。取消等待实际工具停止；未知付费请求只查询或对账，不重放。

创建、连接、暂停与回收操作有界。原生暂停回执不自动证明后端所有 artifact 已完成复制。部署需要独立验证保存、服务重启、恢复和容量/保留策略；单机 Embed 不提供 Cloud 的副本与 HA 保证。

## 供应商替换与资源归属

会话实现消费少量环境操作，具体 E2B 适配负责官方 SDK。没有注册表、插件引擎、SDK options 复制或空的第二实现。

更换默认供应商影响新环境，旧引用仍指向其原供应商。跨供应商文件迁移与内存/系统快照迁移是不同能力，不承诺通用快照无损互通。不支持所需语义时明确失败。

资源创建者负责停止、等待和关闭。进程先停止入口，再等待 HTTP/SSE、投递、模型、工具及供应商操作，最后关闭连接。收尾失败不能报告已成功取消。

## 配置与结构

SQL-first migration 是唯一结构源码：dbmate 执行，Kysely 查询，类型与 schema 从一次性新库生成。已应用历史只前向修正，不从开发库反推或手改生成物。

PostgreSQL 权限用原生 SQL/psql，Redis 权限用原生 ACL。部署从 `config/.env` 显式投影各进程凭据；应用不获得管理员身份。模型、数据库、存储长期凭据以及宿主 home、仓库、Docker socket 不进入沙箱。

源码按实际行为聚合。规则不依赖 SQL/HTTP/SDK，数据库不决定 UI 文案。只有真实资源身份与生命周期需要 class。没有真实消费者不建共享包、转发层、空目录或框架。

# 架构

只写**不随功能变化**的部分:要证明什么、拓扑、权威归属、边界在哪、不建什么。

怎么剪一个视频、skill 怎么写 —— 见 `skills/`。
每条决定后面的数字都是量过的,量的脚本在 `docs/probes/`。

## 0. 这个仓库要证明一件事

pexo 把能力切成工具直接调用。这里给模型一个真的文件系统和一条真的命令行。

**同一份 brief、同一批素材,哪边剪得更好、返工更少。**

已经测过一次。三个规格不一致的源片(`1920x1080@24` 带音轨 · `720x1280@30` 竖屏 · `640x480@15`),
要一条 6 秒 `1280x720@30` 的 montage。`concat` demuxer 在这组素材上必挂 —— 编码、分辨率、帧率、
流布局四样全对不上。

agent 自己 `ffprobe` 了三个源,自己 `ls` 到并读了 skill,选了 `concat` filter 逐路归一化,用
`force_original_aspect_ratio=decrease` + `pad` 而不是硬拉,渲完抽一帧回看。**118 秒,8 次工具
调用,1 次自己爬起来的错误,$0.0354。** 抽帧人眼核对过:竖屏那条加了黑边,没有变形。

**这个判断如果封装成一个 `concat(clips)` 工具,是我们替它做的。**

对照还没做。同一组素材 pexo 的 media-orchestrator 交出什么,是下一件事 —— 在那之前 §0 只有一半。

## 1. 拓扑

```
浏览器 ──► web ──会话──► server ──队列──► agent ─────────► 模型
       ◄──────SSE──────────┘              │  pi 跑在这个进程里
                                          ├──命令/文件──► 沙箱 ──调生成──► gateway ──► 厂商
                                          │              (一轮一租一销毁)   (真 key 只在这)
                                          └──► 流 · 数据库 · 对象存储
```

- **server 和 agent 分开,理由是生命周期不是性能。** 一轮跑十几分钟,HTTP 连接是秒级的 ——
  前端修个样式发一次版,不能把所有在途对话掐死。中间放队列不是 RPC:**队列就是让两条生命周期
  互不影响的那条缝**,server 重启不打扰在途的轮,agent 重启 server 照样收消息。
- **gateway 从第一天就单独。** 沙箱里跑的是模型现编的命令,那里不能有任何长期凭据。它跟 agent
  的权限无关 —— agent 本来什么都有。单独是因为**沙箱是不可信的那一方**。
- **web 单独一个进程,理由还是生命周期。** 它只发页面和把 `/api` 透传给 server:改个样式发一次
  前端,API 不重启;API 重启,页面不跟着掉。透传而不是给 API 开 CORS,是为了让浏览器只面对一个
  源 —— cookie、`EventSource`、fetch 都不用各自对一遍策略,API 也不必知道世上有哪些源。
  **登录就该落在这一层**(现在是一行占位)。那天起两件事同时成立:API 不能再从别处直接访问,
  因为它信这个头。
- **pi 跑在 agent 进程里,沙箱是它的远程文件系统和 shell。** 理由在 §2。
- **gateway 只读请求体里的一个字段:`model`。** 别的一律原样转发。这是唯一的例外,是被真实
  事故逼出来的:一次生成因为参数不合法被拒,agent 把它读成「这个模型不可用」,自己换了一个模型
  把片子生成出来了 —— 没有任何东西拦它,唯一的痕迹是它写在 notes 里的一句话。**skill 拦不住,
  因为 skill 脚本 agent 能读,脚本能做的事它能直接做。** 所以这条只能在这里。配置里不写
  `models` 就是不限,写了就只付这几个的钱。

容量量过:pi 自身底座 186MB,每个在途会话 8.2MB(重负载,32 条消息、每轮一坨 ffmpeg 量级输出)。
**一台 4C8G 的 agent 扛 100 路在途对话。** 在那之前不做水平扩展。

## 2. 为什么 pi 跑在我们进程里,不在沙箱里

两条路的差别只有一行是真的:

```
循环在我们进程   上下文在我们内存      模型 key 永远不进沙箱
循环在沙箱      上下文在沙箱内存      沙箱必须能出网调模型
```

**第二行右边那格就是整条网关存在的理由。** 循环在沙箱里跑,它必须能调到模型,那就不能把真 key
塞进去,得给它一个只认一次性 token 的转发口 —— 于是模型流量和生成流量都得过网关。

循环在我们这边,模型 key 根本不进沙箱,网关只剩一件事:**skill 脚本调 seedance 那类生成 API 时
不让脚本拿到真 key。** 范围小一个数量级。

代价是上下文压在我们进程上。量过了,8.2MB 一路,不是问题。

**什么时候该重新想:** 单进程扛不住并发的那天。到那天先量 `rss`,不要凭感觉。

## 3. 权威

| 事实           | 谁说了算                                    |
| -------------- | ------------------------------------------- |
| 这段对话是什么 | 数据库里的 AG-UI `Message[]`                |
| agent 记得什么 | 数据库里的 session entries(harness 的 JSON) |
| 文件是什么     | 对象存储                                    |
| 流里的东西     | **都不是真相**                              |

**同一段对话有两份记录,回答两个不同的问题:**

- **`Message[]`** —— 人翻页看到的。`ActivityMessage` 就在 AG-UI 的 `Message` 联合里,所以刷新
  就是一条 `MESSAGES_SNAPSHOT`,中间没有翻译步骤可以搞错。
- **session entries** —— 下一轮喂回模型的,含工具调用、工具结果、压缩条目,**没有人会读**。
  量过:4 条消息 6 个 entry、1658 字节,跨进程重建验过,模型记得住前面说过什么。

### 3.1 三层存储,按「这句话说完了没有」切

量过:**131 个字符的回复 = 33 次 text delta**,约四个字符一次。一条两千字的回复就是五百次事件。

|                        | 流  | 数据库 |
| ---------------------- | --- | ------ |
| 文本碎片(五百条)       | ✓   | ✗      |
| 拼好的整句             | ✓   | ✓      |
| 活动 `running`         | ✓   | ✗      |
| 活动 `done` / `failed` | ✓   | ✓      |
| 产物 · 待拍板          | ✓   | ✓      |
| 推理                   | ✓   | ✗      |

**活动那两行是要点。** 转圈的状态进了库,用户第二天刷新会看到一个永远在转的圈 —— 那一轮早结束
了,没人会再去关掉它。只有落定的才进库。推理同理:它是模型的草稿纸,不是对话。

**流必须在进程外,这是 §1 推出来的不是选出来的。** SSE 连在 server,轮跑在 agent,内存里的发射器
只够到一半。而且流得带位置:用户合上笔记本、地铁里断一下,重连要从「我最后收到的是哪一条」接着
读 —— 没有位置的流把这两件事变成页面上的一个洞。

**推出去的东西不是真相。** 前端不能把流里收到的存成状态:存了会在某次刷新之后和库里对不上,而且
**不报错,只是安静地不一样**,没人知道该信哪个。

- **沙箱里的一切都不是真相。** 它一轮一销毁,下一轮要用的必须先落对象存储。
- **未提交的模型输出不是真相。** 可以显示,不落库。
- **派生而非存储:** 能从已有记录查出来的东西不建表。

## 4. 结果三态

```
succeeded   确定成功
failed      确定失败,重试安全
unknown     不知道,重试可能重复外部后果
```

生成一条视频要花钱。**任何外部调用拿不到确定信号就是 `unknown`,永不被猜成前两者,永不自动重放。**

这条纪律住在 skill 脚本里,不住在我们的代码里 —— 因为调生成的是脚本。脚本必须在轮询之前先把
job id 写进工作区文件,这样进程死掉之后那次调用还找得回来。

**但这纪律有一半在边界上:工作区必须在 `finally` 里带出来,失败的那一轮也带。** 第一版把带出写在
成功路径上,实测炸了 —— 一轮在提交生成之后七秒放弃,`.jobs/` 连同沙箱一起销毁,钱花了,没有任何东西
记得它买了什么,下一轮会再买一次。**轮次失败恰恰是这件事最要紧的时候。** 带出本身出错只记日志不抛:
在一轮已经在失败的路上,抛出去只会把「模型拒绝了」换成「我们没收拾干净」。

## 5. 沙箱边界

沙箱 adapter 只有四个函数:跑命令、读文件、写文件、建目录。四条规矩都是踩出来的,不是设计出来的:

**env 必须自己构造,绝不转发 pi 给的那份。** 量过:pi 交给 `exec` 的是**宿主机的整个环境,73 个
变量**,含 `SSH_AUTH_SOCK` 和全部代理变量。第一版我顺手 `{...opts.env}` 了,测试把它抓出来的。

**宿主机要有一个真实的空目录当 cwd。** pi 的 bash 工具会先在本地 `existsSync(cwd)`,即使操作全
转发也一样。这个目录只为过检查,不写任何东西。

**system prompt 里只能出现容器路径。** 路径映射管得了 cwd 参数,管不了命令字符串里的路径。实测
第一次报错就是 agent 去 `cd` 一个宿主机路径。

**`grep` / `find` / `ls` 三个工具必须关掉。** 它们的 `rg` / `fd` 二进制跑在宿主机上,不转发 ——
只有 `bash` / `read` / `write` / `edit` 是真能转发的。让 agent 用 bash 里的 grep/find/ls。

还有一条不是规矩是事实:**两次 bash 调用之间没有常驻 shell**,`cd` 和 `export` 不保留。

还有一条是白捡的:凭据和网关地址是**每条命令用 `-e` 带进去的,不在建容器的时候设**。于是
`docker exec <sandbox> env` 里根本看不见 `VID_TURN_TOKEN` —— 它只在某一条命令活着的那几秒里存在。
这不是设计出来的,是「沙箱不感知配置」那条要求的副产品,但它正好把凭据的暴露窗口压到了一条命令。

**注册是按名字替换的,而且是静默的。** 验过:四个内置工具注册四个同名的,全部被替换,注册表里
没有重复项。危险恰恰在这 —— harness 升级改个名、或者这里打错一个字母,agent 手里照样有个能用的
`bash`,只不过它拿着我们的环境在我们的磁盘上跑 ffmpeg,**什么都不会抛**。所以开机自检:每个工具
自带来源标记,我们注册的是 `inline`,没换掉的内置是 `builtin`(这个区分专门验过)。对不上就起不来。

**厂商名字只准出现在这个 adapter 和组装根里。**

```bash
grep -rl 'docker\|e2b\|aliyun' apps/agent/src   → sandbox/docker.ts, main.ts
```

`main.ts` 命中是对的:**总得有一个地方点名用哪个实现**,那就是它,而且只有它。规则第一版写成「只准出现在
adapter 里」,当场就被正确的代码违反了 —— 一条被对的代码违反的规则,错的是规则。
守它的理由是具体的:E2B 生产环境不给自部署、注册也没过去;阿里云 FC 的 SDK 宣称兼容 E2B;腾讯
Cube 是 Apache 2.0 能自己部署。**这三个之间一定会换。**

## 6. 可见性

线上的形状是 **AG-UI 1.0**,不是我们发明的。我们只拥有它留给生产者的那一格:`activityType`
和它的 `content`。三种 —— 一个人能做的事只有三件:看着活儿在跑、打开产出的东西、回答一个只有
他能答的问题。

**默认不可见。** 没有规则的一律丢。agent 读文件、翻 skill、跑 ffmpeg、重试一次失败的上传 ——
一个都不到屏幕上。反过来做(「看着像内部的就藏」)会在厂商加一个新事件类型的那天漏。

脚本主动打一行才可见:

```
::vid {"id":"render-1","activityType":"step","content":{"label":"正在渲染","state":"running"}}
```

前缀加一个 JSON。**不发明 key=value 语法** —— 那就是写解析器,而解析器是一件会写错的东西。

`id` 是 AG-UI 的 message id,不在 payload 里:**活动落定就是同一个 id 再发一次**,因为
`ACTIVITY_SNAPSHOT` 默认 replace。`running`/`done`、问和答,各是一条消息不是两条 —— 所以投影里
不需要一个状态机去记「哪些圈还在转」。

三条是量出来的:

**必须去重。** 工具的部分输出是**累积量不是增量**。实测同一条公告在流里出现 3 次。

**不能无条件信任文本增量。** 推理走 AG-UI 的 `REASONING_*` 通道,单独验过两次(带工具、不带
工具)都是干净分开的。但三次真实跑里有**一次**网关把 `<thinking>...</thinking>` 内联进了正文。
偶发也得挡 —— 「用户偶尔看见模型的内心独白」在产品里是事故。

**一条流式片段的代价不能跟着对话长度涨。** 这条还没被违反,写在这里是因为它的烂法是已知的。

**产出物:脚本报路径,链接由我们铸。** 脚本手里没有对象存储的凭据,也不该有,所以它公告的是
工作区里的相对路径;边界立刻把这一个文件搬出去,换成一个短期 URL 再放行。**换不成就整条丢掉**
—— 把内部路径推到屏幕上正是 §6 要防的那件事,而且那种链接点开也是空的。搬出去这件事发生在公告
的当下,不等轮次结束:人看见东西出现,下一秒就会去点。

**重放必须幂等。** 浏览器连上来先收一份 snapshot,随后是把这份 snapshot 构建出来的那些事件被
原样重放一遍(流里还存着)。第一次真实打开页面时,整段对话显示了两遍,第二份还没有正文 ——
增量全落到了第一份上。所以 `TEXT_MESSAGE_START` 是「就地重来」而不是「再追加一条」:重放会把
snapshot 已经说过的东西原样重建一遍,而一个开头没赶上的回复也还能接着长。

**思考跟着它那一轮结束一起消失。** 它是屏幕上唯一不进存储的东西,所以重载时根本没法把它放回
正确的位置 —— 实测就是在一段已经结束的对话底部堆了七个折叠的「Thinking」。不存就不该留。

### 6.1 AG-UI 里我们故意不用的两样

**`TOOL_CALL_*` 一个都不发。** 协议有完整的工具调用事件,发了就是把 `bash` 和 `ffmpeg` 推到用户
脸上。用户看到的活动来自 skill 脚本主动打的那一行,不是从工具调用推导的 —— 这是 §8 的直接后果,
不是 AG-UI 不够用。

**`rawEvent` 不填。** 协议留了这个字段给「provider 原生事件,原样带着,给调试用」。填了就等于
把 harness 的词汇送到浏览器,§6 最后那条当场作废。**这是一次故意的不遵循**,写在这里是因为不写
的话下一个人会以为是漏了。要调试就在 agent 进程里打日志,那边本来就认识那些词。

**`RUN_STARTED` / `RUN_FINISHED` / `RUN_ERROR` 必须发。** 协议原文是 mandatory ——
它们是浏览器判断「这一轮开始了没、结束了没、是成了还是崩了」的唯一依据。一度漏掉过。

**harness 的事件名不准离开它的 adapter。** 它们一旦长进投影,再长进存储,再长进前端,换 harness
就是改所有地方。pi 是 0.85.1,还没到 1.0。

## 7. skill 和 extension 是两种东西

|               | 是什么      | 跑在哪               | 谁能写                     |
| ------------- | ----------- | -------------------- | -------------------------- |
| **skill**     | 数据 + 脚本 | 沙箱里               | 我们、运营、以后可能是用户 |
| **extension** | 代码        | **我们的服务器进程** | 只能是我们                 |

两个都叫「定制化」,长得像,坐在信任边界的两边。

extension 有一种加载方式是从磁盘路径读 `.ts` 运行时编译执行(pi 依赖 `jiti`)。在本地开发是好
东西;在多租户服务里那是远程代码执行的口子。**只用 `extensionFactories` —— 我们自己写的函数编
进服务里,永远不从路径加载。**

**skill 的索引可以完全不落盘。** 验过:`skillsOverride` 直接塞内存里的 skill 对象,进了 system
prompt。脚本还是要在沙箱里,索引不用。

## 8. agent 感知什么

**凡是 agent 需要感知的,只能在沙箱里或者在 skill 里。其余一切对它不可见。**

推论:**零自定义工具。** 每多一个自定义工具,就是多一件它被迫感知的基础设施。调 seedance 是
skill 里一个 shell 脚本,不是一个 `generate_video` 工具。

这条守的不是隔离 —— 它敲 `env` 就能看见网关地址。守的是**不给它理由去看**。

## 9. 编排成本可以忽略,这是一个决定

量过:一条 6 秒片子 $0.0354。成本目标是 **1 分钟视频 15–30 美元**。就算 1 分钟的活复杂十倍,
模型 token 也就 $0.35 上下,**占预算 1–2%**。

**所以不为省 token 做任何妥协设计。** 不裁上下文、不用小模型跑子任务、不缓存中间结果、不为了
少一次调用把两件事塞进一个 prompt。该给的上下文就给,该让它多看两眼就多看两眼 —— 省下的那点钱
在 seedance 一次调用面前不值一提,而省法带来的复杂度是永久的。

**什么时候该重新想:** 编排成本超过单条视频预算 10% 的那天。

## 10. 明确不建

workflow 引擎 · provider/model registry(`ModelRuntime` 就是) · 统一的媒体接口 ·
任何自定义工具(§8) · 任务 owner / 回调中心(pi 有 `sendCustomMessage(deliverAs)`) ·
自己写上下文压缩 · 自己算 token 和钱(`getSessionStats()`) ·
把 pi 的事件当成核心 wire(§6) · skill 检索管线(这个量级用不上)

前四条我在设计过程中都建过,都被否了。

## 11. 还没解决的

**长渲染活得比沙箱久。** seedance 渲一条几分钟到半小时,容器是一轮一销毁的。两条路:脚本在容器
里自己等(容器得一直活着,pi 的 bash 还有超时),或者任务活过这一轮、回来时 `sendCustomMessage`
塞回对话(机制现成,但沙箱没了,文件得先落对象存储)。倾向第二条,**没验过**。接第一个真实生成
任务之前必须先解决。

**装配 pi 用哪个入口。** 现在用的是 `createAgentSession` 这个便利包装,然后一路跟它较劲 —— 替换
工具只能绕 extension,因为包装不透出 `baseToolsOverride`,而底层的 `AgentSessionConfig` 直接收。
**给服务器用大概率该走底层构造器,没验。**

**hyperframes 那半边是空的。** §0 证的是 ffmpeg 这条路的手感,合成没碰。

**和 pexo 的对照口径。** §0 的后半句。
